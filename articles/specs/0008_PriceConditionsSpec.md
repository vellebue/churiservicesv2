# Price Conditions

This spec is used to describe price conditions that are used to determine the final price of an article item depending on the
context of a certain order where this price should be issued.

## Entities

The set of entities to manage price conditions are described below:

- PriceCondition represented in database with table PRICE_CONDITIONS

  - conditionId: Long primary key generated by sequence SEQ_PRICE_CONDITIONS.

  - subtypeId: Long, required, references PriceConditionSubtype.subtypeId. The condition type is derived from the referenced subtype, so it is not stored again on this entity.

  - scope: Char, required, describes the scope for this discount condition:
    - 'L' : Line condition, it is applied for an order item that references this price condition.
    - 'H' : Heading condition, it is applied for the whole order.
    - 'D' : Equipment allowance deduction, to be ignored on sale process, retained for accountancy process.

    Note: scope 'D' is intentionally decoupled from conditionType — it is not restricted to PROV conditions, since additional business cases may need this behaviour in the future. The allowed combinations of scope and conditionType are validated at the application layer once the business rules are settled. The sale/accountancy pipeline must treat scope 'D' as the authoritative "skip on sale" signal, regardless of conditionType.

  - evaluation: Char, required, describes the strategy to eval this price condition:
    - 'D': Disjoint strategy. The condition is considered if it is present on, at least, one conditions source.
    - 'J': Joint strategy. The condition is considered if it is present on all conditions sources.

  - description: String 512 chars. Contains the description for this price condition.


- PriceConditionType: represented in database by C_PRICE_CONDITION_TYPES table.

  - conditionType: 4 chars, primary key, is the mnemonic for a certain price condition type.

  - description: 256 chars, required. It describes the type of condition.

  - key: 100 chars, required, it is the I18N key to describe this condition type in several languages for messages property files.

  The set of constant values for condition types are as below:

| conditionType | description          | key                               |
|---------------|----------------------|-----------------------------------|
| FARE          | Base Article Price   | priceCondition.type.fare          |
| DISC          | Discount             | priceCondition.type.discount      |
| TAXE          | Tax Condition        | priceCondition.type.tax           |
| PROV          | Accounting Provision | priceCondition.type.prov          |

  NOTE: Price condition types cannot be altered through the price condition services.

- PriceConditionSubtype: represented in database by C_PRICE_CONDITION_SUBTYPES table:

  - subtypeId: Long primary key generated by sequence SEQ_PRICE_CONDITION_SUBTYPES.

  - conditionType: 4 chars, required, references PriceConditionType.conditionType, is the mnemonic for the price condition type this subtype belongs to.

  - conditionSubtype: 4 chars, required, is the mnemonic for the price condition subtype.

  - description: 256 chars, required. It describes the subtype of condition.

  - key: 100 chars, required, it is the I18N key to describe this condition subtype in several languages for messages property files.

  The pair (conditionType, conditionSubtype) must be UNIQUE (constraint UK_PRICE_CONDITION_SUBTYPES_MNEMONIC).

  These are the initial condition subtypes to load this table initially:

| conditionType | conditionSubtype | description                       | key                               |
|---------------|------------------|-----------------------------------|-----------------------------------|
| FARE          |    FARA          | Base Article Price for articles   | priceCondition.subtype.fare.fara  |
| FARE          |    FARS          | Base Article Price for services   | priceCondition.subtype.fare.fars  |
| DISC          |    DISS          | Standard discount                 | priceCondition.subtype.disc.diss  |
| DISC          |    DICO          | Commercial discount               | priceCondition.subtype.disc.dico  |
| TAXE          |    VAT           | VAT Tax                           | priceCondition.subtype.taxe.vat   |
| TAXE          |    PERS          | Personal Tax                      | priceCondition.subtype.taxe.pers  |
| TAXE          |    SPEC          | Special Tax                       | priceCondition.subtype.taxe.spec  |
| PROV          |    STDP          | Standard provision                | priceCondition.subtype.prov.stdp  |
| PROV          |    RAPP          | Rappel provision                  | priceCondition.subtype.prov.rapp  |

NOTE: Price condition subtypes cannot be altered through the price condition services.

- PriceConditionValue: represented in database by PRICE_CONDITION_VALUES

  - valueId: Long primary key generated by sequence SEQ_PRICE_CONDITION_VALUES.

  - conditionId: Long, required, references the PriceCondition this PriceConditionValue belongs to.

  - valueType: Char, required, it represents the type of value for this value condition.
    
    - 'A': Amount: this condition value represents an absolute value applied once per article reference unit.

    - 'P': Percentage: this condition value represents a percentage value to apply from a reference previous amount.

  - value: Decimal(12,6), required, represents the numeric value for this value condition. Use BigDecimal type to handle in Kotlin. It could be positive or negative.

  - beginDate: Date, required, it represents the beginning date of validity for this condition value.

  - endDate: Date, optional, it represents the ending date of validity for this condition value.

  For a certain set of price conditions values related to a single PriceCondition, the overlapping of beginDate-endDate intervals is not permitted.

## Use Cases

Develop the following services.

- A service to create a PriceCondition with at least one PriceConditionValue with a beginDate and empty endDate.

- A service to update a PriceCondition (replacing the whole price condition and its dependencies). Note that a price condition with no values is not permitted.

- A service to get a price condition and its price condition values by conditionId.

- A service to delete a price condition and its values

- A service to retrieve PriceCondition and its PriceConditionValues filtering by the following fields (all of them optional). Use paged responses as defined in agent.md:

  - PriceCondition.subtypeId.

  - PriceCondition.scope.

  - PriceCondition.evaluation.

  - PriceCondition.description (Wildcard '*' is permitted here).

  - PriceConditionValue.beginDate. 

  - PriceConditionValue.endDate.
